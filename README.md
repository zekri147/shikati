# شيكاتي

تطبيق ويب صغير لإيلوناك لمتابعة شيكات العملاء من زوهو بوكس، ثم تسجيل إيداعها في بنك AGB (في المرحلة الثانية).

الحالة الحالية: **المرحلة الأولى — قراءة فقط.** الخادم لا يحتوي أي طلب كتابة إلى زوهو.

عنوان التطبيق المنشور:

```
https://shikati.zekri3047.workers.dev
```

## البنية

| الجزء | الأداة |
|---|---|
| الخادم والواجهة | خادم كلاود فلير (Cloudflare Workers) يقدّم الملفات الثابتة من مجلد `public` |
| التخزين | قاعدة كلاود فلير (D1): المستخدمون، الجلسات، محاولات الدخول، سجل العمليات، تخزين مؤقت |
| زوهو | رمز تجديد من تطبيق (Self Client)، يجدّده وسيط صغير في غوغل لأن كلاود فلير لا يصل إلى خادم الرموز الأمريكي لزوهو (راجع `RELAY.md`) |

```
src/index.ts            توجيه الطلبات وحماية الصفحات
src/auth.ts             الدخول، الجلسات، الأدوار، حد المحاولات
src/admin.ts            إدارة المستخدمين وسجل العمليات
src/zoho.ts             رمز الوصول وطلبات القراءة من زوهو
src/modules/cheques.ts  منطق أقسام الشيكات
src/modules/index.ts    قائمة الوحدات: تُضاف هنا الأقسام الجديدة لاحقاً
public/                 الواجهة (عربية، من اليمين لليسار، الوضع الداكن افتراضي)
migrations/             جداول قاعدة البيانات
scripts/create-user.mjs إنشاء أول حساب مدير
```

## لماذا D1 وليس KV

القفل ضد الضغط المزدوج في المرحلة الثانية يحتاج إدخالاً ذرّياً يرفض الطلب الثاني فوراً، و(KV) يتأخر توزيع تحديثاته بين الخوادم. كما أن سجل العمليات وعدّ محاولات الدخول يحتاجان قراءة دقيقة وبحثاً بالتاريخ والمستخدم.

## قواعد التصنيف

- **تنتظر الإيداع (الرقم الرئيسي):** مجموع الأقسام الثلاثة «في الحوزة» أدناه.
- **في الحوزة:** الحالة «في الحوزة» والحساب «Cheques in Hand»، ثم تُقسم حسب الوجهة: ELONAC، أو ROSTOMIA، أو فارغة.
- الشيكات «في الحوزة» المسجّلة في حساب آخر (مثل Endorsed Cheques) أو وجهتها «Autre Fournisseur» لا تدخل في أي قسم.
- **آخر 5 إيداعات:** القائمة لا تحتوي تاريخ الإيداع، فالترتيب بآخر تعديل للدفعة.
- قائمة الشيكات تُخزَّن دقيقة واحدة، وزر «تحديث» يجلبها من زوهو مباشرة.

## الأمان

- الرموز السرية مشفّرة بخوارزمية (PBKDF2-SHA256) بـ 100000 تكرار وملح لكل مستخدم.
- الجلسة في ملف تعريف (cookie) من نوع HttpOnly وSecure وSameSite=Strict، تنتهي بعد 12 ساعة (المتغير `SESSION_HOURS`).
- قاعدة البيانات تخزّن بصمة رمز الجلسة فقط، لا الرمز نفسه.
- بعد 5 محاولات فاشلة لنفس الاسم خلال 15 دقيقة يُقفل الدخول 15 دقيقة، وبعد 20 محاولة من نفس العنوان كذلك.
- إيقاف المستخدم يحذف جلساته فوراً.
- كل طلب كتابة يُرفض إن لم يأتِ من نفس الموقع، وسياسة أمان المحتوى (CSP) تمنع أي شيفرة خارجية.
- رسائل الخطأ المعروضة عامة، والتفاصيل تُكتب في سجل الخادم فقط.

## التشغيل لأول مرة

الطريق الأسهل من لوحة كلاود فلير دون أي أداة على جهازك: راجع ملف `DEPLOY.md`.

أو من سطر الأوامر:

```bash
npm install
npx wrangler login
npx wrangler d1 create shikati
```

انسخ قيمة `database_id` التي يطبعها الأمر الأخير إلى ملف `wrangler.toml`، ثم:

```bash
npm run db:migrate:remote
npx wrangler secret put ZOHO_RELAY_URL
npx wrangler secret put ZOHO_RELAY_KEY
npm run deploy
node scripts/create-user.mjs --remote
```

بدل الأمر الأخير يمكنك وضع السر `SETUP_TOKEN` وإنشاء أول مدير من صفحة `/setup`، وهي تعمل مرة واحدة فقط.

بعدها افتح العنوان الذي يطبعه أمر النشر، وادخل بحساب المدير، وأنشئ حساب أمين من صفحة الإدارة.

## رمز تجديد زوهو

يحصل عليه الوسيط في غوغل بنفسه بالدالة `exchangeCode`، ويحفظه في خصائصه. الخطوات في الملف `RELAY.md`.

## التجربة المحلية

انسخ `.dev.vars.example` إلى `.dev.vars` واملأ القيم، ثم:

```bash
npm run db:migrate:local
node scripts/create-user.mjs --local
npm run dev
```

## إضافة قسم جديد لاحقاً

أنشئ ملف وحدة في `src/modules/` يطبّق الواجهة `AppModule`، وأضفه إلى `src/modules/index.ts`، ثم أنشئ ملف العرض في `public/js/modules/` وسجّله في `window.ShikatiModules` بنفس المعرّف.
